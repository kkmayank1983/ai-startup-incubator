Session 4: Memory Management

Solving the Goldfish Problem. Give your AI a long-term memory while mastering the engineering of the "Desk Space."

60 Minutes Level: Advanced Junior

Session Mission

In this lab, you will define Statelessness, visualize the Context Window, build manual memory loops, and implement professional Conversation Chains to make your bot remember everything.

1. The Goldfish Brain (Statelessness)

In Session 3, we learned that AI models are powerful Next-Word Guessers. They do not think or store memories. They only respond to the text they can currently see.

Now test this:
Tell the AI: My name is Chiara.
Then ask: What is my name?

It forgets.

Why?
Because every time you run llm.invoke(), it sends a completely new request to the API. The model only sees the text included in that specific request.

It has no hard drive.
No saved chat history.
No automatic memory between calls.

This is called Statelessness.

Every time you press Enter, the AI starts fresh — like a goldfish with a 5-second memory.

The Result: The AI responds that it doesn't know your name. It forgot everything between the two calls! This is Statelessness.

2. The AI’s Desk (Context Window & Tokens)

In Session 2, we introduced the Context Window and compared it to a desk. Let’s revisit that idea — because now it becomes critical. The AI can only “see” what fits on that desk.

Everything counts:

  • System instructions
  • Chat history
  • Your message
  • The AI’s reply

Text is measured in Tokens. If the model supports 8,000 tokens and you use 7,900, only 100 remain.

If the desk gets full, older messages fall off. This is called Truncation.

The AI doesn’t choose to forget. The text simply doesn’t fit.

Truncation: If the desk becomes too full, the AI has to throw the oldest papers (messages) in the bin to make room for new ones.

Key Lesson: Memory is limited by the size of the Context Window. It is not infinite.

3. Manual Memory: It’s Just Text

Up until now, every API call has been independent. If we want the AI to behave like it remembers things, we need to control what we send inside each request.

If the AI forgets between requests, how do we fix it? We remind it.
Instead of sending only the new message, we send the entire conversation again. 

chat_history = ""

while True:
    user_input = input("You: ")
    chat_history += f"User: {user_input}\n"

    response = llm.invoke(chat_history)

    chat_history += f"AI: {response.content}\n"
    print(response.content)

Each time the loop runs:

  1. We add the new user message to chat_history.
  2. We send the entire history to the model.
  3. We add the AI’s response back into the history.

From the model’s perspective, it looks like one long conversation.

We did not upgrade the model or install memory hardware.
We simply sent more text.

Memory = Resending previous messages.

🛠 Activity: Building a Manual Memory Loop

We will create a growing string called chat_history to act as the AI's "short-term memory."

  1. In your memory_test.py file, delete the previous code from #Attempt 1 line.
  2. Initialize a variable called chat_history = "".
  3. Create a while True: loop to keep the conversation running.
  4. Use the code below to implement the manual memory logic:
    5. Manual Memory Loop
    chat_history = ""

while True:
    user_input = input("You: ")
    if user_input.lower() == "exit": break

    # 1. Add user input to the history
    chat_history += f"User: {user_input}\n"

    # 2. Send the ENTIRE history string to the AI
    response = llm.invoke(chat_history)

    # 3. Add the AI's response back into the history
    chat_history += f"AI: {response.content}\n"

    print(f"AI: {response.content}")
  5. It should be looking like this :
  6. Run the script and tell the AI your name.
  7. Ask a few unrelated questions.
  8. Now ask "By the way what is my Name?". Observe that it actually remembers your name now.
Observation:
In this activity, the AI will continue remembering your name even after several questions. This is because the entire conversation is sent to the model every time.

However, memory is not infinite. Each AI model has a limit called the Context Window. For example, models like gpt-4o-mini can handle a very large conversation, so the AI may remember your name for hundreds of messages.

If the conversation becomes extremely long, the oldest messages (like the first time you shared your name) will eventually be removed. When that happens, the AI will forget.

Key Lesson: We did not make the AI smarter. We simply resend the entire conversation every time.
Memory = Resending previous messages.

4. Automation: Converstaion Buffer Memory & Conversation Chain

Managing strings manually gets messy quickly. Professional engineers use tools that act like a Notebook to keep track of the chat automatically.

Conversation Buffer Memory: A LangChain tool that writes down every message in a running "buffer" (notebook). ConversationBufferMemory keeps the entire conversation in order.

Each time the user sends a message:

  • The new message is added
  • Previous history is preserved
  • The full conversation is sent back to the model

The model can “remember” earlier details — not because it has real memory, but because we keep resending the stored chat history.

Important: This memory is temporary. It exists only while the script runs. Restarting the program clears it.

In simple terms: It is an automatic chat history manager.

Conversation Chain: A ready-made loop that connects the LLM (Brain), the Memory (Notebook), and the User input.

Instead of manually building and resending chat history, it automatically:

  • Receives user input
  • Adds it to memory
  • Sends the full conversation to the model
  • Returns the response

It simplifies conversation logic into one object. When used with ConversationBufferMemory, it creates a chatbot that remembers earlier messages during the session.

In simple terms: ConversationBufferMemory stores the chat. ConversationChain uses it when talking to the model.

🛠 Activity: The Professional Structure

Let's use LangChain to handle the memory logic automatically and cleanly.

  1. Create a new file named pro_memory.py.
  2. Import the required memory tools and set up the ConversationChain:
    3. pro_memory.py
    from langchain_classic.chains import ConversationChain
from langchain_classic.memory import ConversationBufferMemory
from langchain_openai import ChatOpenAI
from dotenv import load_dotenv

load_dotenv()
llm = ChatOpenAI(model="gpt-4o-mini")

# 1. Create the 'Notebook' (Memory)
memory = ConversationBufferMemory()

# 2. Create the 'Chatbot' (Chain)
bot = ConversationChain(llm=llm, memory=memory)

# 3. Use .predict() instead of .invoke()
print(bot.predict(input="My name is Chiara."))
print(bot.predict(input="What is my name?"))
  3. Run the script and notice how much cleaner the code is. The "Chain" handles the resending of text for you!
Note:
You may see a warning message saying ConversationChain is deprecated. This does not affect the activity. The code will still run correctly because we are using langchain-classic for learning conversational memory concepts. The tool still works but LangChain plans to replace it in the future.

5. The Stress Test & “The Receipt”

THE RECEIPT ANALOGY

Every new message includes the entire previous conversation again. If your history is 500 tokens long, Message #11 costs you 510 tokens. You are paying for the full conversation every time you hit Enter.

🧾 The Stress Test

Tell your bot 5–10 facts about yourself. Then keep chatting.
Now ask:
What was the first thing I told you?

If the conversation becomes extremely long, the model may eventually forget the earliest facts.

Every new message resends the full history. If your chat is 500 tokens long:
Message #10 costs ~500 tokens
Message #11 costs ~510 tokens

Longer memory:

  • Better context
  • Higher cost
  • Faster desk overflow

🛠 Activity: The Memory Stress Test

Let's see how much information we can pack onto the AI's "Desk" before things get expensive or crowded.

  1. Run your pro_memory.py script.
  2. Provide at least 5–10 different facts to the bot (e.g., "I live in Melbourne," "My dog is named Rex," "My favorite color is orange").
  3. Continue chatting about other things for a minute.
  4. Now ask: “What was the very first fact I told you?”
  5. Observe: Did the AI still remember the first fact? Every time you sent a new fact, you were "paying" tokens for all the previous facts!
Key Lesson: Long memory improves context, but it increases token usage, increases cost, and fills the Context Window faster. Memory must be managed carefully.

In every request, the AI is still a next-word guesser. It does not gain real memory — we control what it sees.

By managing chat history, we control context. By controlling context, we control behavior.

You have now moved from writing simple prompts to engineering conversational systems.

⚙ Troubleshooting & FAQs

❓ The AI Still Forgets My Name

Check the following:

  • You are using ConversationChain and not calling llm.invoke() directly.
  • Your memory object is correctly passed into the chain.
  • You are using bot.predict() instead of llm.invoke().

Remember: If you bypass the chain, memory will not be used.

❓ NameError: ConversationChain or ConversationBufferMemory Not Defined

This means the classes were not imported correctly or the other reason could be that you have not installed langchain-classic package in your virtual environment.

To install that you should run the following command: pip install langchain-classic

Make sure you added:

                    from langchain_classic.chains import ConversationChain
                    from langchain_classic.memory import ConversationBufferMemory

❓ Infinite Loop Running Forever

If you used while True:, your program will not stop automatically.

Press Ctrl + C in the terminal to stop the loop.

❓ Memory Resets When I Restart the Script

This is expected behavior. ConversationBufferMemory is temporary. It stores messages only while the program is running.

Permanent storage will be covered in a later session.

❓ The Bot Forgets After Long Conversations

This happens because of the Context Window limit. When the token limit is reached, older messages are removed.

This is called Truncation.

Common Mistakes

  • Calling llm.invoke() instead of bot.predict().
  • Creating memory but not passing it into ConversationChain.
  • Restarting the script and expecting memory to persist.
  • Using extremely long text and hitting the Context Window limit.

Did You Know?

Every time you send a new message to your bot, it has to reread the entire conversation again. That means by message #20, the AI might be rereading thousands of words just to answer one question.

Memory makes your bot smarter — but also slower and more expensive.
