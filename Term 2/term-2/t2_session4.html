Session 4: The Context Window

Session 3's AI could only see one character at a time. Today we give it a memory — and then we run an experiment to prove it matters.

60 Minutes Level: Junior Architect

Session Mission

Load a real book as training data, cut it into context windows, then train the same AI three times — with a memory of 1, 2 and 4 characters — and read the difference in what it writes.

0. Quick Recap: Where We Are

Your AI is learning to write by guessing one character at a time.

Session 2 — we taught it the alphabet. Every character became a number.
Session 3 — we taught it to guess. It looks at one character and guesses the next.
Session 4 — today — we give it a memory. Now it can look back at many.

📘 From Session 3 — and the problem it left behind

Session 3 built the guesser: a Score Table of opinions, softmax to turn those into percentages, and a weighted dice roll to pick the next character.

But it could only ever see one character. Shown an "h", it had no idea whether the word so far was "T-h" or "s-h".

That is the one problem we fix today — and then we prove it worked.

1. Why One Letter Is Never Enough

Try it yourself. What letter comes next?

h  →  next letter?  No idea. Could be anything.
he  →  next letter?  Maybe "l"... or "r"... or "y".
hel  →  next letter?  Probably "l".
hell  →  next letter?  Almost certainly "o".

Every extra letter made your guess better. Nothing about you got smarter — you just got more to go on.

The number of characters the AI is allowed to look back at is called the context window. In code we call it block_size. Session 3's AI had a context window of 1. Today we make it bigger, and see what that does.

Today's plan — four steps

  1. Load Shakespeare — a real 1 MB book as training data.
  2. Cut it into context windows — and see the practice questions inside them.
  3. Run the experiment — train the same AI with a context window of 1, then 2, then 4, and read what it writes.
  4. Talk to it — type your own text and watch your AI respond.

import os
import torch

# --- Open the book ---
current_dir = os.path.dirname(__file__)
input_file = os.path.join(current_dir, "input.txt")

with open(input_file, 'r', encoding='utf-8') as f:
    text = f.read()

# --- The tokenizer from Session 2 ---
chars = sorted(list(set(text)))
stoi = { ch:i for i,ch in enumerate(chars) }
encode = lambda s: [stoi[c] for c in s]
itos = { i:ch for i,ch in enumerate(chars) }

def decode(ids):
    return ''.join([itos[i] for i in ids])

vocab_size = len(chars)      # how many different characters exist

# --- Turn the WHOLE book into numbers ---
data = torch.tensor(encode(text), dtype=torch.long)

print(f"Dataset Size: {len(data)} tokens.")
print(f"Different characters: {vocab_size}")
print(f"First 10 tokens: {data[:10]}")
print("Decoded:", decode(data[:10].tolist()))

🔍 Stuck on the tokenizer code? Open this for a line-by-line explanation
The line What it does
chars = sorted(list(set(text))) Read it inside-out. set() throws away duplicates (1 million characters → 65). list() puts them in a list. sorted() fixes the order so everyone gets the same numbers.
stoi = { ch:i for i,ch in enumerate(chars) } enumerate hands you a position and a character: (0,'\n'), (1,' '), (2,'!')… We save each as character → number.
encode = lambda s: [stoi[c] for c in s] lambda is a short way to write a small function. This one says: for every character, look up its number.
itos = { i:ch for i,ch in enumerate(chars) } Same as stoi, stored the other way round: number → character.

3. Cut the Book Into Context Windows

We cannot hand the AI a million characters at once. So we take a small chunk — block_size characters long — and turn it into a practice question.

The clever bit: we never have to write the answers. They are already in the book, one step to the right.

4. The Experiment: Does a Bigger Context Window Actually Help?

This is the whole point of today

We have been told that more context makes better predictions. Now we prove it.

You will train the same AI, on the same book, for the same amount of time — three times. The only difference will be how far back it is allowed to look. Then you read what it writes.

🛠 Activity 3: Train It Three Times

  1. Create a new file called context_experiment.py in Term_2.
  2. Copy in the code below. You do not need to understand every line — we build all of this properly in Sessions 5 and 6. Today you are running an experiment.
context_experiment.py
import torch
import torch.nn as nn
import torch.nn.functional as F

from data_pipeline import data, vocab_size, decode

# =========================================================
#  THE ONLY LINE YOU CHANGE.  Run with 1, then 2, then 4.
# =========================================================
CONTEXT_SIZE = 1
# =========================================================


class ContextModel(nn.Module):
    """Looks at CONTEXT_SIZE characters and guesses the next one."""

    def __init__(self):
        super().__init__()
        self.embed  = nn.Embedding(vocab_size, 24)
        self.hidden = nn.Linear(CONTEXT_SIZE * 24, 128)
        self.output = nn.Linear(128, vocab_size)

    def forward(self, idx):
        e = self.embed(idx)              # each character becomes 24 numbers
        e = e.view(idx.shape[0], -1)     # lay the whole window out in one row
        h = torch.tanh(self.hidden(e))   # think about them all together
        return self.output(h)            # score every possible next character


torch.manual_seed(1337)
model = ContextModel()
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3)

print(f"Training with CONTEXT_SIZE = {CONTEXT_SIZE} ...")

running_loss = 0
average_loss = 0

for step in range(1, 6001):

    # Grab 64 random windows from the book
    ix = torch.randint(0, len(data) - CONTEXT_SIZE - 1, (64,))
    x = torch.stack([data[i : i + CONTEXT_SIZE] for i in ix])   # the context
    y = torch.stack([data[i + CONTEXT_SIZE] for i in ix])       # the next character

    loss = F.cross_entropy(model(x), y)

    optimizer.zero_grad()
    loss.backward()
    optimizer.step()

    running_loss += loss.item()

    if step % 1500 == 0:
        average_loss = running_loss / 1500
        print(f"  step {step:5d} | average loss {average_loss:.3f}")
        running_loss = 0

print(f"\n>>> FINAL LOSS with CONTEXT_SIZE = {CONTEXT_SIZE}  is  {average_loss:.3f}")


# --- Now let it write ---
print(f"\n===== SHAKESPEARE, WRITTEN WITH CONTEXT_SIZE = {CONTEXT_SIZE} =====\n")

window = [0] * CONTEXT_SIZE
result = []

for _ in range(300):
    xb = torch.tensor([window[-CONTEXT_SIZE:]], dtype=torch.long)
    probs = F.softmax(model(xb), dim=-1)
    next_char = torch.multinomial(probs, num_samples=1).item()
    result.append(next_char)
    window.append(next_char)

print(decode(result))

🔬 Zoom in: what ONE training example looks like

Step 1 of Phase 1 says "open the book at a random spot". Here is what that means, with CONTEXT_SIZE = 4: 

input.txt   ├────────────────────────────────────────────────┤   1,115,394 characters
                              ▲
                        a random spot
                              │
                    ┌─────────┴─────────┐
                    │  t   h   e   ␣    │   c        <-- ONE training example
                    └───────────────────┘   ▲
                       the CONTEXT (x)      │
                       4 characters      the ANSWER (y)
                                         1 character

The AI is shown "the " and has to guess "c". It is never told the answer in advance — it guesses first, then finds out.

That is all a training example is. The code does 64 of these at once, 6,000 times over.

So how much of the book actually gets used?

Let's do the arithmetic — it is simpler than it looks.

6,000 steps  ×  64 windows each  =  384,000 training examples
384,000 examples  ×  5 characters each  =  1,920,000 characters read

The book is 1,115,394 characters long. So your AI reads about 1.7 times the whole book — but never front-to-back. It reads it as 384,000 tiny 5-character snippets, grabbed at random from everywhere in the text.

CONTEXT_SIZE Characters per example Total characters read How many times the book
1 1 + 1 = 2 768,000 0.7 ×
2 2 + 1 = 3 1,152,000 1.0 ×
4 4 + 1 = 5 1,920,000 1.7 ×

This is a real reason bigger context windows cost more: the same 6,000 steps force the computer to read more of the book every single step.

It cannot be copying — here's the proof

1,115,394
characters of Shakespeare go IN
→
22,361
numbers come OUT

Everything your AI learned is squeezed into about 22,000 numbers — roughly 50 times smaller than the book. There is nowhere to hide a copy of Shakespeare in there.

So it cannot memorise and replay the text. All it can store are patterns: which characters tend to follow which. That is why the output looks like Shakespeare without being any actual line from the play.

What you just proved

You changed one number. You did not make the AI bigger, or smarter, or train it for longer. You did not give it a dictionary or a grammar rule.

You only let it look further back — and the writing got better.

That is the context window. It is why "how much can this AI remember?" is one of the first questions engineers ask about any language model.

5. So Why Not Use a Massive Context Window?

Fair question. If 8 beats 1, why not 1,000,000 and be done with it?

Let's calculate the cost instead of guessing. To work out which characters matter, the AI has to compare every character in its memory with every other one (you build exactly that in Session 5). So 8 characters means 8 × 8 comparisons.

🛠 Mini Activity: Calculate the Real Cost

Create memory_cost.py, paste this in, and run it. It finishes instantly.

memory_cost.py
for block_size in [8, 64, 256, 2048, 1000000]:

    comparisons = block_size * block_size
    gigabytes = comparisons * 4 / 1_000_000_000

    print(f"block_size = {block_size:>9,}  ->  {comparisons:>19,} comparisons  =  {gigabytes:>12,.4f} GB")
Output
block_size =         8  ->                   64 comparisons  =        0.0000 GB
block_size =        64  ->                4,096 comparisons  =        0.0000 GB
block_size =       256  ->               65,536 comparisons  =        0.0003 GB
block_size =     2,048  ->            4,194,304 comparisons  =        0.0168 GB
block_size = 1,000,000  ->    1,000,000,000,000 comparisons  =    4,000.0000 GB

4,000 GB = 4 terabytes — for one chunk of text. A good laptop has 16 GB. You would need about 250 laptops to handle a single sentence.

Notice the shape of it: double the context window and the cost goes up four times, not two. That is why bigger context windows are a headline feature companies charge more for.

6. Talk to Your AI

Read this before you get excited

You are about to type into an AI that you built from nothing. That is genuinely worth being proud of. But be clear about what you have made:

It will not answer your questions. It has never seen a question and an answer. It has only ever done one thing — look at CONTEXT_SIZE characters and guess the next one. So it will take whatever you type and continue it in the style of Shakespeare. That is the whole trick, and watching it fail at questions teaches you more than watching it succeed.

🛠 Activity 4: Give It Something to Continue

  1. Open context_experiment.py and set CONTEXT_SIZE = 4 (your best model). Save it.
  2. Create a new file called talk_to_your_ai.py and copy in the code below.
talk_to_your_ai.py
import torch
import torch.nn.functional as F

# This runs context_experiment.py first, so your AI trains before you talk to it.
from context_experiment import model, CONTEXT_SIZE
from data_pipeline import stoi, encode, decode

print("\n" + "=" * 55)
print("TALK TO YOUR AI")
print("=" * 55)
print("Type some text and your AI will try to continue it.")
print("Type  quit  to stop.\n")

while True:

    prompt = input("You: ")

    if prompt.lower() == "quit":
        break

    # Your AI only knows the 65 characters that appear in Shakespeare.
    # Anything else has to be removed before it can read your text.
    clean = ''.join(c for c in prompt if c in stoi)

    if clean != prompt:
        print("   (some characters aren't in Shakespeare's alphabet - removed)")

    if clean == "":
        print("   (nothing left for the AI to read - try letters only)\n")
        continue

    # Put your text into the AI's memory window
    window = [0] * CONTEXT_SIZE + encode(clean)

    # Let it continue for 200 characters
    result = []
    for _ in range(200):
        xb = torch.tensor([window[-CONTEXT_SIZE:]], dtype=torch.long)
        probs = F.softmax(model(xb), dim=-1)
        next_char = torch.multinomial(probs, num_samples=1).item()
        result.append(next_char)
        window.append(next_char)

    print("\nAI: " + clean + decode(result) + "\n")

The three things you just learned

  1. It continues text — it does not answer. Every single training example was "here are 4 characters, guess the next one." So that is all it can do. It was never shown a question with an answer attached.

ChatGPT does the same "guess the next token" trick — but with a context window of thousands instead of 4, trained on a huge slice of the internet instead of one play, and then specifically taught to answer questions. You have built the engine. The rest of the course makes it bigger and smarter.

⚙ Troubleshooting & FAQs

❓ FileNotFoundError: input.txt

input.txt must be in the same folder as data_pipeline.py — both inside Term_2.

❓ ImportError: cannot import name 'vocab_size'

Your data_pipeline.py is missing the line vocab_size = len(chars). Add it just above the data = ... line.

❓ NameError: name 'decode' is not defined

You put new code above the tokenizer. Python reads a file top to bottom, so decode must exist before anything uses it. Move your new code to the very bottom.

❓ My experiment prints all the data_pipeline output too

That is normal — importing a file runs it. You can comment out the print() lines in data_pipeline.py if you want a cleaner screen. Only the prints; leave everything else.

❓ My generated text is slightly different from my friend's

The fixed seed (torch.manual_seed(1337)) means everyone should get very similar text, but different PyTorch versions can still shift things a little. Compare the quality — real words, spaces, play layout — not the exact wording.

❓ Why is the target (y) shifted by one?

Because the AI's job is always to predict the next character. Shifting by one lines up every question with its answer automatically.

❓ talk_to_your_ai.py just sits there doing nothing

It is training first — that takes about 30 seconds. Watch for the step 1500 / 3000 / 4500 / 6000 lines. When TALK TO YOUR AI appears, type and press Enter.

❓ Why does it retrain every time I want to chat?

Because we never saved the trained model to disk — it only exists in memory while the program runs. Saving and reloading a model is exactly what Session 7 is about. For now, keep the program open and chat as long as you like before typing quit.

❓ My AI ignores my question completely

That is the correct result, not a bug. It has only ever been trained to continue text, never to answer anything. See section 6 — this is the point of the activity.

❓ Each run takes ages

About 30 seconds is normal. If it is minutes, close other apps. You can also lower 6001 to 3001 — the effect still shows, just less clearly.

❓ My token IDs differ from my friend's

Then you are using different input.txt files. With the same file, sorted() guarantees identical numbers.

SESSION COMPLETE

You gave your AI a memory, proved it mattered with an experiment you ran yourself, and then talked to it.

But notice something. Your AI treats every character in its window as equally important. When you read "The cat sat on the mat because it was tired", your brain instantly links "it" to "cat" and ignores everything else. Your AI cannot do that.

That is why the improvement runs out (as you will find in the homework). Extra memory is useless if you cannot tell the important parts from the noise. Teaching it to focus is Session 5: Self-Attention.

Here are the losses we measured:

Surprise: it stops helping after about 4. Going to 8 changed nothing, and 16 was actually worse — while taking about 45 seconds per run instead of 30.

Why? Look at what our model does with the window:

It lays all the characters out in one flat row and treats every position as equally important.

With 16 characters, most of them are irrelevant noise — and our model has no way to tell the useful ones from the junk. Extra memory it cannot use is just extra cost.

It gets worse the further you push. At a window of 64 the flat model reaches a loss of about 2.13 — worse than it managed with only 4 characters. It is drowning in its own memory.

That is the problem Session 5 solves. You will build attention — a way for the AI to decide which characters in its window actually matter — and run it head-to-head against this model on that same 64-character window. Attention wins, using about 3.2× fewer numbers.

Advanced Task — what to expect

With CONTEXT_SIZE = 1, the AI forgets your prompt immediately — after one character it can only see the character it just wrote.

With CONTEXT_SIZE = 4, the prompt influences the next several characters, so the opening looks far more like a genuine continuation.

This is exactly why a chatbot with a small context window "forgets" what you said earlier in a conversation.

Did You Know?

GPT-3 had a context window of 2,048 tokens. GPT-4 handles up to 128,000. That is the difference between remembering a single page and remembering an entire bookshelf — and you just measured why that is so expensive.
