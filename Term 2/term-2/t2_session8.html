1. The Bug: Watch Your Question Vanish

Since Session 6 the tokenizer has given every whole word its own number — 4,095 of them, one for each different word in the book. Pick a question below, or type your own, and see what the AI actually receives.

What does the AI actually see?

Every word is checked against the 4,095-word list from the physics book. Anything not on the list is thrown away.

The AI sees: —

Two things just went wrong

1. Unknown words are deleted. "What is entropy?" reaches the model as What is. The subject of the question is gone. The model is not choosing to give a random answer — it never got the question.

2. Punctuation is glued on. Try What is gravity? and then What is gravity with no question mark. The list contains gravity? because that exact spelling appears in the book — but travel? and blue? do not, even though travel and blue do. To a word tokenizer, they are completely different words.

And it gets worse inside the book

A word can only be learned if it turns up often. Here is how many of those 4,095 words the model saw exactly once in the whole book:

Last week: whole words
2,304 / 4,095

More than half the vocabulary was seen a single time. You cannot learn a word from one glimpse — so most of the list is dead weight, and 93% of the model's parameters are tied up in that list.

2. The Fix: Read In Pieces

Think about Lego. You do not own one special brick for every possible thing you might build. You own a box of pieces that can build anything. That is exactly what we want for words.

Characters (Sessions 2–5)

gravity
  • Only 65 bricks. Nothing is ever unknown.
  • Every brick is tiny. A 64-brick window is barely a sentence.

Whole words (Sessions 6–7)

gravity
  • One brick, one word. Windows hold whole sentences.
  • 4,095 different bricks. Any word not in the box is deleted.
  • Most bricks were seen once — never really learned.

Word pieces (today)

gravity
  • About 1,000 bricks that can spell any word.
  • Common words stay whole. Rare words split into common pieces.
  • Every piece is seen many times, so every piece gets learned.

The same words, read by today's tokenizer

These are the real pieces your tokenizer will learn from the physics book. Green = pieces glued from letters. Gold = a whole word it decided deserved one piece of its own.

Look at entropy. The book never contains that word — but it does contain ent, ro, p and y many times each. A word it has never seen is just pieces it has seen. And the question mark is now its own piece, so travel? is simply travel + ?.

3. How It Chooses The Pieces: The Glue Rule

Nobody types the pieces in. The tokenizer learns them from the book with one rule, repeated over and over:

The glue rule

Start with single letters. Find the two neighbours that sit next to each other most often. Glue them into one piece. Repeat.

Watch it happen on a tiny sentence. Every count below is calculated live — press Next to glue one pair at a time, or Play to let it run.

Byte-Pair Encoding, one glue at a time

Yellow = the pair about to be glued. Green = the new piece it just made.

Neighbours counted this round

That is the whole algorithm. Do it about 1,000 times on the physics book instead of 8 times on a sentence, and you get 1,024 pieces: the alphabet, plus every common chunk of English the book kept using — the, tion, gravity, even gravitational. Its real name is Byte-Pair Encoding, or BPE, and it is what GPT uses: GPT-2 learned 50,257 pieces this exact way.

🛠 Activity 1: Build the tokenizer

  1. Create a new file called bpe_tokenizer.py.
  2. Copy the code below exactly as shown. The three parts match the three things you just watched: cut into chunks, count and glue, then read new text with the rules it learned.
bpe_tokenizer.py
import re
from collections import Counter

# The three signposts in input.txt. They must stay in one piece,
# so the tokenizer is told about them before it learns anything.
TAGS = ["<|user|>", "<|assistant|>", "<|endoftext|>"]

# How the text gets cut into chunks BEFORE any learning happens:
#   a signpost            <|user|>
#   a word, with the space in front of it kept    " gravity"
#   one punctuation mark, with its space          "?"  or  " ("
#   any other whitespace                           "\n"
# Pieces are only ever glued together INSIDE a chunk, so a piece can
# never spill across two words.
CHUNK = re.compile(
    r"<\|user\|>|<\|assistant\|>|<\|endoftext\|>| ?[A-Za-z0-9]+| ?[^A-Za-z0-9\s<]|\s|."
)


def glue(chunk, pair):
    """Replace every (a, b) that sits side by side in chunk with a+b."""
    out = []
    i = 0
    while i < len(chunk):
        if i < len(chunk) - 1 and (chunk[i], chunk[i + 1]) == pair:
            out.append(pair[0] + pair[1])
            i += 2
        else:
            out.append(chunk[i])
            i += 1
    return tuple(out)


class BPETokenizer:
    """Learns which letters belong together, then reads ANY text."""

    def __init__(self):
        self.merges = []     # the glue rules, in the order they were learned
        self.stoi = {}       # piece  -> number
        self.itos = {}       # number -> piece
        self.cache = {}      # remembers chunks it has already broken up

    def train(self, text, vocab_size):
        # 1. Cut the book into chunks and count how often each one appears.
        counts = Counter(CHUNK.findall(text))

        # 2. Every chunk starts life as a row of single characters.
        #    (A signpost stays as one whole piece.)
        table = {}
        for chunk, n in counts.items():
            table[(chunk,) if chunk in TAGS else tuple(chunk)] = n

        # 3. The starting alphabet: every single character in the book.
        pieces = sorted({p for row in table for p in row})

        # 4. Glue the most common neighbouring pair. Repeat until full.
        while len(pieces) < vocab_size:
            pairs = Counter()
            for row, n in table.items():
                for a, b in zip(row, row[1:]):
                    pairs[(a, b)] += n
            if not pairs:
                break
            best = max(pairs, key=pairs.get)
            self.merges.append(best)
            pieces.append(best[0] + best[1])
            table = {glue(row, best): n for row, n in table.items()}

        self.stoi = {p: i for i, p in enumerate(pieces)}
        self.itos = {i: p for i, p in enumerate(pieces)}

    def break_up(self, chunk):
        """Turn one chunk into pieces using the learned glue rules."""
        if chunk in self.cache:
            return self.cache[chunk]
        if chunk in TAGS:
            row = (chunk,)
        else:
            # A character the book never contained cannot be read. Skip it.
            row = tuple(c for c in chunk if c in self.stoi)
        for pair in self.merges:
            if len(row) < 2:
                break
            row = glue(row, pair)
        self.cache[chunk] = row
        return row

    def encode(self, text):
        ids = []
        for chunk in CHUNK.findall(text):
            ids.extend(self.stoi[p] for p in self.break_up(chunk))
        return ids

    def decode(self, ids):
        return "".join(self.itos[i] for i in ids)

One detail worth noticing

The three signposts — <|user|>, <|assistant|>, <|endoftext|> — are told to the tokenizer up front, so they always stay in one piece. If they were ever chopped up, the model could not tell where a question ends and an answer begins.

import os
import torch
from bpe_tokenizer import BPETokenizer

# --- Open the book ---
current_dir = os.path.dirname(__file__)
input_file = os.path.join(current_dir, "input.txt")

with open(input_file, 'r', encoding='utf-8') as f:
    text = f.read()

# --- The tokenizer, now BPE: words broken into PIECES ---
# Session 2 used single characters. Session 6 used whole words.
# Today we start from the characters again, then glue the most
# common neighbours together until we have VOCAB_SIZE pieces.
# Any word can be spelled from pieces, so nothing is ever unknown.
VOCAB_SIZE = 1024

tokenizer = BPETokenizer()
tokenizer.train(text, VOCAB_SIZE)

stoi = tokenizer.stoi            # piece  -> number
itos = tokenizer.itos            # number -> piece
vocab_size = len(stoi)           # how many different PIECES exist
encode = tokenizer.encode
decode = tokenizer.decode

# --- Turn the WHOLE book into numbers ---
data = torch.tensor(encode(text), dtype=torch.long)

print(f"Dataset Size: {len(data)} tokens.")
print(f"Different pieces: {vocab_size}")
print(f"First 10 tokens: {data[:10]}")
print("Decoded:", repr(decode(data[:10].tolist())))

    7. Stop — Which Loss Is Better?

    You cannot compare today's loss with last week's

    Loss is "how surprised was the model by the correct next token". Last week a token was a whole word. Today a token is a piece of one. That is like comparing two students' marks when one sat a 22-question test and the other a 39-question test made of smaller questions. The numbers live on different scales.

    So today we judge the two models the way you would judge a person: what can it read, and is it answering or reciting.

    Yardstick 1: Can it read the question?

    • Count the words of a question that survive the tokenizer.
    • Last week: anything not on the list vanished.
    • Today: every character gets through.

    Yardstick 2: Is it copying?

    • Slide a 5-word window along the answer.
    • If that exact run of words is in the book, it was copied.
    • A high copy rate means reciting, not answering.

    Yardstick 3: How big is the brain?

    • Fewer parameters doing the same job is a win.
    • Smaller trains faster and needs less memory.
    For the curious: is there a fair single number?

    Yes — divide the surprise by the number of characters instead of tokens, so both models are marked per letter. On fresh slices of the book: last week's model scores about 0.04 bits per character, today's about 0.16. Lower looks better — but be careful what "better" means here. The book is only 137,000 characters. A model that is almost never surprised by it has memorised it. Last week's model was surprised less because it had learned the book by heart, which is exactly the problem Session 7 flagged. Yardstick 2 shows the same thing from the other side.

# How much of an answer is copied word-for-word from the book?
# We slide a 5-word window along the answer and check whether that exact
# run of words appears anywhere in input.txt.
book_words = text.split()
book_runs = {tuple(book_words[i:i + 5]) for i in range(len(book_words) - 4)}

def copied(answer):
    w = answer.split()
    if len(w) < 5:
        return 0.0
    runs = [tuple(w[i:i + 5]) for i in range(len(w) - 4)]
    return 100 * sum(r in book_runs for r in runs) / len(runs)


def ask(model, enc, dec, question, seed, n_tokens):

    prompt = f"<|user|>\n{question}\n<|assistant|>\n"
    ids = enc(prompt)
    out = model.generate(torch.tensor([ids]), max_new_tokens=n_tokens)[0].tolist()
    answer = dec(out[len(ids):])
    for tag in ("<|endoftext|>", "<|user|>", "<|assistant|>"):
        answer = answer.split(tag)[0]
    return " ".join(answer.split()[:45])         # first 45 words, for both

    import torch

# No training this time. The model is loaded from the file you saved.
from attention_engine import model
from data_pipeline import encode, decode, itos

model.load_state_dict(torch.load("qa_model_v3.pth"))
model.eval()

print("\n" + "=" * 55)
print("ASK YOUR AI A PHYSICS QUESTION")
print("=" * 55)
print("Type a question. Type  quit  to stop.\n")

while True:
    question = input("You: ")
    if question.lower() == "quit":
        break

    # Show exactly what it reads. Every character makes it through now.
    pieces = [itos[i] for i in encode(question)]
    print("   (it read: " + "|".join(pieces) + ")")

    # Laid out exactly like every block in input.txt.
    prompt = f"<|user|>\n{question}\n<|assistant|>\n"
    ids = encode(prompt)

    out = model.generate(torch.tensor([ids]), max_new_tokens=120)[0].tolist()

    # Keep only the new text, and stop at the first signpost.
    answer = decode(out[len(ids):])
    for tag in ("<|endoftext|>", "<|user|>", "<|assistant|>"):
        answer = answer.split(tag)[0]

    print("\nAI: " + answer.strip() + "\n")

    10. What This Fixed — And What It Didn't

    Fixed today

    • It reads every question, including words the book never had.
    • Punctuation, capitals and plurals no longer break words.
    • The brain is 70% smaller and trains faster.
    • It stopped reciting: its answers are mostly its own words.

    Not fixed today

    • Its own words are often wrong words. Spelling from pieces is harder than picking whole words, and 399 examples is not much practice.
    • It still cannot know anything the book does not say. It reads "entropy" perfectly and has nothing to say about it.

    Why that is the right trade

    • Last week's fluent answers were copies. Fluent-but-copied cannot grow.
    • Today's model reads anything and composes. Give it more book, and it has somewhere to go. That is the next step — and it is a data problem, not an engine problem.

    Measured: what more training does

    We trained today's model for 6,000 steps instead of 2,500 (about 14 minutes). Loss fell from 0.42 to 0.26, and the answers started opening correctly — "What is inertia?" produced the book's inertia answer word-for-word, and "What is gravity?" began "Gravity isn't just a simple…" before wandering. The copy rate rose to 23%. That is the pattern to expect from a small model on a small book: the longer you train, the more it recites. Better answers that are not recitals need more text to learn from, not more laps of the same text.

    ⚙ Troubleshooting & FAQs
    ❓ RuntimeError: size mismatch … loading qa_model_v2.pth

    Last week's model has a 4,095-word vocabulary; today's engine builds itself for 1,024 pieces. tokenizer_showdown.py handles this by building a second engine with PredictionEngine(len(words)) for the old weights. If you see this error, you are loading old weights into the new engine — check which file goes into which model.

    ❓ Every script pauses for 15–20 seconds before printing anything

    That is the tokenizer learning its 1,000 glue rules again, every single time data_pipeline.py is imported. It is the same "we never saved it" problem as Session 7 — a real project would save the rules to a file once. It is a good stretch task if you finish early.

    ❓ KeyError: '\n' — but I thought that was fixed?

    It was: attention_engine.py should say NEWLINE = stoi.get("\n"). Today that line gets a real number again, because \n is back as a piece. If you still see this error you are running an old copy of the engine from before Session 6's fix.

    ❓ I asked about a made-up word and it answered confidently

    Look at the (it read: …) line first: it read your invented word perfectly, as pieces. Then it wrote a physics-flavoured answer about nothing. That is the honest limit of today — the tokenizer fixed reading; knowing only comes from what was in the book. Reading a word is not the same as knowing what it means.

    ❓ My question had an emoji or a strange symbol and it disappeared

    The alphabet is every character in the book. A character the book never contained cannot be read, so break_up() skips it. Real tokenizers start from raw bytes so nothing is ever skipped — a good advanced upgrade.

    ❓ Last week's scripts (see_the_heads.py, showdown.py) now crash

    Expected. They were written for the word tokenizer and the word-vocabulary model. Once data_pipeline.py switched to pieces, the engine it builds no longer matches qa_model_v2.pth. That is exactly why today's showdown builds the old engine separately.

    ❓ My loss numbers look nothing like last week's

    They should not. Loss is surprise per token, and a token changed from a whole word to a piece of one. Compare what the model reads and what it answers; if you want one number, use the per-character version explained in Section 7.
