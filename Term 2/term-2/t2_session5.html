Session 5: The Self-Attention Mechanism

Session 4 proved that more memory helps — until it doesn't. Today we find out why it stopped helping, and build the real mechanism that fixes it: Queries, Keys, and Values.

60 Minutes Level: Junior Architect

Session Mission

Build a real, working Self-Attention head — the actual matrix math, not just the idea — and prove it beats every model Session 4 produced — head-to-head, on the exact same data, with a third of the numbers.

0. Quick Recap: Where We Are

Session 2 — the tokenizer. Every character became a number.
Session 3 — the guesser. A Score Table, wrapped in a PredictionEngine class and a generate() loop, looks at one character and guesses the next.
Session 4 — memory. A context window (block_size) lets it look back at several characters at once.
Session 5 — today — focus. We teach it which of those characters actually matter.

The cliffhanger Session 4 left behind

You ran the context experiment three times, then the homework pushed it further, to block_size = 8 and 16. Here is what happened:

block_sizeFinal loss
12.500
41.932
81.935 — no improvement
161.958 — worse
642.127 — worse still

More memory made things worse past a point. That sounds backwards — so here is the actual reason, in plain terms:

  1. Every extra slot is a brand new thing to learn. Session 4's model kept a completely separate set of weights for "the character 1 step back", another set for "2 steps back", another for "3 steps back", and so on. Going from 4 characters to 64 didn't make it cleverer — it made it 16 times bigger, with 16 times more to work out.
  2. Most of those extra characters are useless. To guess the letter after th, a letter from 40 characters ago almost never helps. But the flat model has no way to say "ignore that one". It is forced to give every slot a weight and just hope training sorts it out.
  3. Same practice time, far more to learn. Every run trained for the same 6,000 steps. Spread that same effort across a much bigger pile of mostly-junk connections and each one ends up learned worse. So the loss goes up.

So the problem was never "not enough memory". It was having no way to choose what to pay attention to. A bigger window just handed the model more noise to wade through. That is exactly what we fix today.

One more word you'll need: batch_size

block_size is the size of one flashcard — how many characters make up a single practice question. batch_size is a different number: how many flashcards the AI looks at together, in one go, before it updates itself.

You have actually already used this, without a name for it. In Session 4's context_experiment.py, this line grabbed 64 random windows at once:

ix = torch.randint(0, len(data) - CONTEXT_SIZE - 1, (64,))

That 64 is the batch size. Training on one flashcard at a time works, but it is slow and each update is noisy — one lucky or unlucky example can push the AI the wrong way. A bigger batch means each update is based on an average over many examples, so it moves in a steadier, more reliable direction. Today's code calls it exactly what it is: batch_size = 64.

3. Intuition First: Queries, Keys, and Values

To perform Self-Attention, every character on our "Digital Desk" plays three roles:

Query
"What am I looking for?"
Key
"What do I contain?"
Value
"The info I share."

Think of it like a Detective (Query) checking a Clue (Key). If the Query matches the Key, the Detective takes the Evidence (Value) from that clue and adds it to the case.

That's the idea in one sentence. Nice — but it's not magic, and it's not a metaphor either. It's real arithmetic, and it's small enough to do by hand. Let's actually do it.

The Query Experiment — worked on paper

Before we build anything, let's see one attention score actually happen. Two clues are sitting on the desk. Each one is described by just two numbers:

Clue 1 (Key)
how vowel-ish : 0.9
how space-ish : 0.1
"I contain a vowel."
Clue 2 (Key)
how vowel-ish : 0.1
how space-ish : 0.9
"I contain a space."

Now a character asks a question — that question is the Query, and it is also just two numbers. To score a question against a clue you multiply the numbers that line up, then add them up. Bigger answer = better match.

Question A: "find me a vowel"
Query = [ 1.0 , 0.2 ]
vs Clue 1: 1.0×0.9 + 0.2×0.1 = 0.92 ✓
vs Clue 2: 1.0×0.1 + 0.2×0.9 = 0.28

Clue 1 wins.

Question B: "find me a space"
Query = [ 0.1 , 1.0 ]
vs Clue 1: 0.1×0.9 + 1.0×0.1 = 0.19
vs Clue 2: 0.1×0.1 + 1.0×0.9 = 0.91 ✓

Clue 2 wins.

What that means: the clues never changed — the same four numbers sat there the whole time. Only the question changed, and a different clue won. That is the entire trick: attention is the model asking "what am I looking for right now?" and scoring everything on the desk against it.

Engineering Insight

We just chose those Query and Key numbers to make the point. A real model is never told them — it has to learn what they should be, from the data. And it has to do it for every character against every other character at once, not one pair at a time. That is exactly what we build next.

4. How The Math Actually Works

Forget code for a minute. Here is the entire mechanism, worked out with real numbers, on three tiny characters: T, H, E. Each one is described by just 2 numbers, so every step fits on screen and you can check the arithmetic yourself.

Every diagram on this page moves. They start playing when you scroll to them, and each one has a Watch again button underneath — no need to reload the page. Watch them as many times as you like.

STEP 0

Each character already has a small card of numbers (from the token + position embeddings you met last time). Here are the three we'll use:

Character cards (x)
num 1num 2
T1.00.0
H0.01.0
E1.01.0

What do "num 1" and "num 2" mean? Nothing we chose. In the last section we pretended two numbers meant "vowel-ish" and "space-ish" to make the idea concrete — but a real model invents its own two traits during training, and they almost never have tidy English names. All that matters is that each character ends up with its own pair: T is all trait 1, H is all trait 2, E is a bit of both. From here we'll just call them trait 1 and trait 2.

STEP 1

Every character asks three questions of itself: "What am I looking for?" (Query), "What do I contain?" (Key), "What can I offer?" (Value). It answers all three the same way — by taking its own card and rewriting it three different ways.

The rewriting is done by three small tables of numbers: Wq, Wk and Wv. These three tables are the only things in the whole mechanism that the AI learns. Everything after Step 1 is fixed arithmetic that never changes.

Where do the numbers in Wq, Wk and Wv actually come from?

Nobody chooses them. They start as random noise — on the model's first ever step they are meaningless. Then, every training step, the model makes a guess, finds out how wrong it was, and every number in these three tables gets a tiny nudge in whatever direction would have made that guess less wrong. Do that a few thousand times and the tables settle into a pattern that works.

That means no human can say in advance what they should be. The tidy numbers below were picked by us, so the arithmetic stays checkable on paper. A real trained table is an ugly mess of numbers like 0.0473 and -0.2811 that nobody can read at a glance — but it does exactly the same job.

The only matrix rule you need

Take a row from the left table and a column from the right table. Multiply the numbers that line up, then add those up. That single answer goes in the box where that row and that column cross. Repeat for every crossing. That's it — that's all "matrix multiplication" means.

Here are the three tables we'll use. Read each one column by column: every column is a recipe for one output number — "take this much of trait 1, plus this much of trait 2."

Wq — makes the Query
out 1out 2
trait 11.00.5
trait 20.01.0
Wk — makes the Key
out 1out 2
trait 10.50.0
trait 21.01.0
Wv — makes the Value
out 1out 2
trait 11.00.0
trait 20.01.0
  • Wq says: Query number 1 = trait 1, copied straight across. Query number 2 = a half-share of trait 1 plus all of trait 2. So a character's question is built mostly out of trait 2, with a splash of trait 1 mixed in.
  • Wk says: Key number 1 = half of trait 1 plus all of trait 2. Key number 2 = trait 2 only. A different recipe, so the same card advertises something different from what it asks for.
  • Wv says: hand the card over untouched. This head happened to land on a "pass it straight through" Value table. Real trained heads are never this tidy — we picked easy numbers on purpose.

So what does the multiplication actually do? The character's card says what it is. Multiplying by Wq turns that into what it is searching for. Multiplying by Wk turns the very same card into what it advertises to others. Multiplying by Wv turns it into what it hands over if chosen. One character, one card, three different jobs — because three different weight tables.

In code, this is three lines: q = self.query(x), k = self.key(x), v = self.value(x).

STEP 2

Now every character's Query is compared against every character's Key, using exactly the same row-times-column rule. A high number means "this looks like what I'm searching for."

In code this is one line for the whole table at once: q @ k.transpose(-2, -1). We need that .transpose() first, because both Q and K are 3 rows × 2 columns — and our rule needs columns on the right-hand side. So K gets tipped over: its rows become columns.

K, tipped onto its side. Same six numbers, just rearranged.

Now multiply. Nine crossings, so nine answers — every character's Query against every character's Key.

The finished score table:

asking ↓ / about →THE
T0.501.502.00
H0.001.001.00
E0.502.503.00
STEP 3

Before we go further, these scores get scaled down — divided by the square root of how many numbers are in each Key (here, √2 ≈ 1.41). Without this, scores made of bigger vectors would naturally come out bigger for no meaningful reason, and one score could end up so much larger than the rest that softmax (next step) gives it almost 100% of the attention every time — even when it isn't really that much better a match. Dividing by √(size) keeps scores in a stable, comparable range no matter how big the vectors are.

Scaled scores (÷ √2)
asking ↓ / about →THE
T0.351.061.41
H0.000.710.71
E0.351.772.12
STEP 4

"No cheating" — the mask from the diagram you'll see again below. T is only allowed to know about T. H can know about T and H. E can know about all three. We block the rest by setting them to negative infinity — which, after the next step, turns into exactly 0%.

Masked scores
asking ↓ / about →THE
T0.35−∞−∞
H0.000.71−∞
E0.351.772.12
STEP 5

Softmax turns each row into percentages that add up to 100% — the same Weighted Dice trick from Session 3. A blocked (−∞) score always becomes exactly 0%.

T → 100% 0% 0%
H → 33% 67% 0%
E → 9% 37% 53%

Read row "H": when guessing what comes after H, this head puts 33% of its trust in T and 67% in H itself. Row "E" spreads its trust across all three, leaning most on itself (53%).

STEP 6

Last step: use those percentages to blend the Value cards. Row H's output is 33% of T's Value plus 67% of H's Value. That blend is what gets passed on — the character's new, focused understanding of itself.

And it is the same row-times-column rule one last time: the percentage table multiplied by the Value table. Watch the blocked 0% boxes contribute exactly nothing.

The finished output — one new card per character:

Context vectors (output)
num 1num 2
T1.0000.000
H0.3300.670
E0.6250.909

Hold on — what is a "context vector"?

It is just the character's card, rewritten. ("Vector" is only a posh word for a list of numbers — which is exactly what a card is.)

Before attention, T's card said one thing: "I am the letter T, sitting in position 1." That was all it knew — and it was the same card every time, no matter what sentence T turned up in.

After attention, that card also carries a share of every character T was allowed to look at, mixed in by how much T cared about each one. Same size card. But now it means "T, in this particular sentence" instead of just "T".

That is the whole reason for the name — the character plus its context. Look at row H: 0.330, 0.670. Those numbers are not random. They are 33% of T's card and 67% of H's own card, blended. H's new card literally has a piece of T inside it. That is a thing Session 4's model could never do.

That's it. That's the whole mechanism.

Six steps: turn each character into Query/Key/Value, score every pair, scale, mask the future, softmax, blend the Values. Every attention head in every Transformer on Earth — including the ones inside ChatGPT — does exactly this. The only things that change at bigger scale are how many numbers each card holds, and how many heads run at once.

One gap left: give it somewhere to think

Look back at Step 6. The output is only ever a blend of Value cards — a weighted average. Attention can mix information around, but it can never actually process it or combine it in a new way. We add a small Feed-Forward layer straight after: a tiny two-step network that takes what attention gathered and works something out from it.

Both new pieces — attention's output, and the Feed-Forward's output — get added back onto the original card, not swapped in for it. That's a residual connection: a highway that lets the original information skip past untouched, so nothing gets lost, while the new insight rides on top.

5. Building It For Real

Before you touch any code — what's happening to Session 3's work?

Session 3 built generation_engine.py: a PredictionEngine class and a generate() loop. Nothing about that lesson was wrong, and we are not deleting it. That file stays exactly as it is — it's a real, working record of the simplest possible version, and it's worth keeping.

What Session 3 taught you is the shape: a class that holds the model, and a loop that asks it for one character at a time. That shape doesn't change today, next session, or ever — it's how every version of this model works, all the way up to production-grade systems.

What changes is what's inside that shape. 🛠 Activity 1: Building a Real Attention Head

THE LEVEL UP

Today: A token card + a position card, one real Attention Head doing exactly the six steps you just worked out by hand, a Feed-Forward layer, both added back on with residual connections.

attention_engine.py
import torch
import torch.nn as nn
from torch.nn import functional as F
from data_pipeline import vocab_size, stoi

# Small, real numbers. Session 6 grows these up.
n_embd = 96        # numbers used to describe each character
block_size = 64    # how many characters the AI can see at once
batch_size = 64    # how many windows get trained on together, per step

# The character that ends a line of the play. We use .get() rather than
# stoi["\n"] because Session 6 swaps the tokenizer over to whole words,
# and then there is no newline token at all - .get() returns None
# instead of crashing.
NEWLINE = stoi.get("\n")

class SelfAttentionHead(nn.Module):
    """One Attention Head. Learns its own Query, Key and Value
    numbers, instead of us picking them by hand like the T/H/E
    example. Does exactly those 6 steps, for every character
    against every character, all at once."""
    def __init__(self, head_size):
        super().__init__()
        self.key   = nn.Linear(n_embd, head_size, bias=False)
        self.query = nn.Linear(n_embd, head_size, bias=False)
        self.value = nn.Linear(n_embd, head_size, bias=False)

        # STEP 4's "no cheating" mask
        self.register_buffer(
            "tril", torch.tril(torch.ones(block_size, block_size))
        )

    def forward(self, x):
        B, T, C = x.shape

        k = self.key(x)     # STEP 1
        q = self.query(x)   # STEP 1
        v = self.value(x)   # STEP 1

        wei = q @ k.transpose(-2, -1) * k.shape[-1] ** -0.5  # STEP 2 + 3

        wei = wei.masked_fill(self.tril[:T, :T] == 0, float("-inf"))  # STEP 4

        wei = F.softmax(wei, dim=-1)  # STEP 5

        # Save this so the Focus Map can look at it later
        self.last_weights = wei.detach()

        return wei @ v  # STEP 6


class FeedForward(nn.Module):
    """Somewhere for the AI to actually think about what
    attention gathered, instead of just blending it."""
    def __init__(self, n_embd):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(n_embd, n_embd),
            nn.ReLU(),
            nn.Linear(n_embd, n_embd),
        )

    def forward(self, x):
        return self.net(x)


class PredictionEngine(nn.Module):
    def __init__(self, vocab_size):
        super().__init__()

        self.token_embedding_table = nn.Embedding(vocab_size, n_embd)
        self.position_embedding_table = nn.Embedding(block_size, n_embd)
        self.sa_head = SelfAttentionHead(n_embd)
        self.ffwd = FeedForward(n_embd)
        self.lm_head = nn.Linear(n_embd, vocab_size)

    def forward(self, idx):
        B, T = idx.shape

        tok_emb = self.token_embedding_table(idx)                # what is this character?
        pos_emb = self.position_embedding_table(torch.arange(T)) # where does it sit?
        x = tok_emb + pos_emb                                    # combine both cards

        x = x + self.sa_head(x)   # focus, then add the result back in
        x = x + self.ffwd(x)      # think about it, then add that back in too

        logits = self.lm_head(x)  # turn it back into a guess
        return logits

    def generate(self, idx, max_new_tokens, stop_after_lines=None):
        """Writes one character at a time, exactly like Session 3.
        If stop_after_lines is given, it keeps going until it has
        finished that many lines - so you get whole lines of the
        play instead of text that stops in the middle of a word."""
        lines_done = 0
        for _ in range(max_new_tokens):
            idx_cond = idx[:, -block_size:]
            logits = self(idx_cond)
            logits = logits[:, -1, :]
            probs = F.softmax(logits, dim=-1)
            idx_next = torch.multinomial(probs, num_samples=1)
            idx = torch.cat((idx, idx_next), dim=1)

            if stop_after_lines is not None and NEWLINE is not None and idx_next.item() == NEWLINE:
                lines_done += 1
                if lines_done >= stop_after_lines:
                    break
        return idx


model = PredictionEngine(vocab_size)
  • Save the file. Do not run it standalone — vocab_size comes from data_pipeline.py, so this file is meant to be imported.

    • A quick heads-up about speed

    The way you just wrote SelfAttentionHead is the honest, readable version — it's exactly the six steps, in order, so you can see every one of them happen. It also happens to be slower than it needs to be, because it builds the full score table in memory before masking most of it away.

    In Session 6 we swap this for something called Flash Attention — a way of computing this exact same math, exact same answer, but much faster and using far less memory, by never fully building that wasted part of the table in the first place. You don't need to know how it works yet. Just know it's coming, and that it changes nothing about what attention actually does — only how quickly it does it.

    6. Loss, Properly This Time

    The promise from Session 4

    Session 4 used Loss to compare its three runs but said "we build it properly in Session 5." Here it is.

    Loss is a single number for "how wrong the AI's guesses were, on average." Every guess gets compared against the real next character, turned into a percentage the model gave the correct answer, and averaged across the batch. High loss = mostly wrong. Low loss = mostly right.

    A number worth knowing

    Before training, guesses are close to random across 65 possible characters. Loss starts near ln(65) ≈ 4.17. Watch for it to start there and drop.

    import torch
import torch.nn as nn
import torch.nn.functional as F

# Seeded before attention_engine is imported, so the model's
# starting weights are controlled too, not just the training batches.
torch.manual_seed(1337)

from data_pipeline import data, vocab_size, decode, encode, stoi
from attention_engine import model, block_size, batch_size

STEPS = 2000

# How big a nudge each training step gives the weights.
# Session 4 used 1e-3. Attention can safely take bigger steps
# than the flat model - Section 7 explains why we raised it.
LEARNING_RATE = 3e-3

def count_params(m):
    return sum(p.numel() for p in m.parameters())

# ----------------------------------------------------
# CONTENDER 1: Session 4's flat model, unchanged
# ----------------------------------------------------
class ContextModel(nn.Module):
    def __init__(self):
        super().__init__()
        self.embed  = nn.Embedding(vocab_size, 24)
        self.hidden = nn.Linear(block_size * 24, 128)
        self.output = nn.Linear(128, vocab_size)

    def forward(self, idx):
        e = self.embed(idx)
        e = e.view(idx.shape[0], -1)
        h = torch.tanh(self.hidden(e))
        return self.output(h)

torch.manual_seed(1337)
flat = ContextModel()
opt_flat = torch.optim.AdamW(flat.parameters(), lr=LEARNING_RATE)

print(f"Flat model params      : {count_params(flat):,}")
print(f"Attention model params : {count_params(model):,}")
print(f"Attention uses {count_params(flat)/count_params(model):.2f}x fewer numbers\n")

print("Training the FLAT model (Session 4)...")
running = 0.0
for step in range(1, STEPS + 1):
    ix = torch.randint(0, len(data) - block_size - 1, (batch_size,))
    x = torch.stack([data[i:i + block_size] for i in ix])
    y = torch.stack([data[i + block_size] for i in ix])
    loss = F.cross_entropy(flat(x), y)
    opt_flat.zero_grad()
    loss.backward()
    opt_flat.step()
    running += loss.item()
    if step % 500 == 0:
        print(f"  [flat] step {step:5d} | average loss {running/500:.3f}")
        running = 0.0

# ----------------------------------------------------
# CONTENDER 2: your new Attention model
# ----------------------------------------------------
torch.manual_seed(1337)
opt_attn = torch.optim.AdamW(model.parameters(), lr=LEARNING_RATE)

print("\nTraining the ATTENTION model (today)...")
running = 0.0
for step in range(1, STEPS + 1):
    ix = torch.randint(0, len(data) - block_size - 1, (batch_size,))
    x = torch.stack([data[i:i + block_size] for i in ix])
    y = torch.stack([data[i + 1:i + block_size + 1] for i in ix])
    logits = model(x)
    loss = F.cross_entropy(logits.view(-1, vocab_size), y.view(-1))
    opt_attn.zero_grad()
    loss.backward()
    opt_attn.step()
    running += loss.item()
    if step % 500 == 0:
        print(f"  [attn] step {step:5d} | average loss {running/500:.3f}")
        running = 0.0

# ----------------------------------------------------
# Generate from the trained Attention model
# ----------------------------------------------------
# Character 0 is a newline, so this starts it at the beginning of a line.
# stop_after_lines makes it write whole lines instead of cutting off
# in the middle of a word.
context = torch.zeros((1, 1), dtype=torch.long)
sample = model.generate(context, max_new_tokens=500, stop_after_lines=12)[0].tolist()
print("\n" + "=" * 55)
print("YOUR ATTENTION MODEL, WRITING SHAKESPEARE")
print("=" * 55)
print(decode(sample))

# Peek at what it is actually focusing on
# ----------------------------------------------------

ids = torch.tensor([[stoi[c] for c in sentence]])

weights = model.sa_head.last_weights[0]

print("\nFocus Map for 'ROMEO:'\n")
for row, ch in enumerate(sentence):
    print(f"{ch!r:>6} -> ", end="")
    for col in range(row + 1):
        print(f"{weights[row, col].item()*100:5.1f}% ", end="")
    print()

# ----------------------------------------------------
# Talk to it - no second training run needed
# ----------------------------------------------------
print("\n" + "=" * 55)
print("TALK TO YOUR ATTENTION MODEL  (type  quit  to stop)")

    10. Wait — Is This How Real AI Is Actually Trained?

    You have spent two sessions training an AI by taking Shakespeare, feeding it a chunk, and asking it to guess the next character — where the "right answer" is just the same text shifted along by one. It is fair to wonder whether that is a schoolroom simplification.

    It isn't. That is exactly how ChatGPT, Claude and Gemini are trained. Not a simplified version of it — the same rule, run at a size that is hard to picture.

    Stage 1: Pretraining — what you did today

    Take an enormous pile of text. Hide what comes next. Make the model guess. Measure how wrong it was. Nudge every weight a tiny bit towards being less wrong. Repeat.

    The only differences between your run and a real one are size:

    Your model A real one
    Predictsthe next characterthe next token (Session 6)
    Trained onone book of Shakespeare, 1.1 million charactersmuch of the public internet
    Numbers learned64,961hundreds of billions
    Training timea few minutes, one laptopmonths, tens of thousands of GPUs
    The ruleguess the next oneguess the next one

    Why does such a dumb-sounding task produce intelligence?

    Because to get really good at guessing the next character, there is no shortcut — you are forced to learn things. First spelling. Then which letters follow which. Then that ROMEO is usually followed by : and then a new line. Then grammar. Then, at a big enough scale, that a sentence beginning "the capital of France is" ends in one particular word. Prediction is the excuse. Understanding is the side-effect. Your model climbed as far as spelling and layout in four minutes. Same ladder — just the bottom rung of it.

    So why can it not answer questions about the play?

    Because "answer my question" and "continue this text" are two different jobs, and your model has only ever been shown the second one. It has never once been shown an example labelled "here is a question, and here is the answer you are supposed to give" — not one. So when you typed What is gravity? it did the only thing it has ever been rewarded for: it carried on writing, in Shakespeare.

    That is not a bug, and it is not a failure of attention. It is the model doing precisely what it was trained to do. Raw pretraining does not produce a chatbot. It produces a very good text-continuer. ChatGPT is what happens when you take a text-continuer and put it through two more stages.

    The three stages of a real assistant

    Stage What it teaches Trained on You?
    1. Pretraining spelling, grammar, style, facts mountains of raw text, shifted by one ✅ Today
    2. Instruction tuning that a question should be answered, not continued a much smaller, hand-written set of question → good answer pairs ❌ not yet
    3. RLHF which of two decent answers people actually prefer humans ranking the model's own answers ❌ Session 6

    Here is the part worth remembering: stage 2 uses the exact same mechanism you built today. Nothing changes in the code — same attention head, same "guess the next one", same loss. The only thing that changes is what text you feed it. Instead of a play, you feed it thousands of examples that all look like Question: … Answer: …, and it learns that what follows a question is an answer. That is genuinely all "fine-tuning" means.

    Could we do stage 2 on your model, right now?

    Mechanically, yes — you would write out a few hundred Q: … A: … lines about the play and carry on training. And it would learn the shape: ask it something and you would get an answer-looking blob back instead of a stage direction.

    But it would not actually know anything. 64,961 numbers is not enough room to store who Romeo is — it is barely enough to store English spelling. It would either parrot an answer back word-for-word (memorised, not understood) or invent nonsense with total confidence. The mechanism is not the missing piece. Scale is. That is exactly why Sessions 6, 7 and 8 exist: bigger tokens, deeper stacks, a real dataset, and a model you can save and reload instead of retraining every time.

    ❓ If it writes lines, why not cut every training window at the start of a line too?

    Good instinct — and we tried it. It backfires. There are only about 40,000 line starts in the book, but over a million random positions. Cut every window at a line start and the flat model stops learning and starts memorising which character tends to follow each line opening. Its loss drops from 2.430 to 1.689 and it beats the Attention model — not because it got cleverer, but because we accidentally set it an easier, smaller task.

    That is why the windows are cut from random positions. A model that has memorised the answers looks brilliant on the data it trained on and falls apart on anything new. Spotting the difference between learning and memorising is one of the most important skills in this whole course.

    ❓ Why does it retrain every time I run the file?
